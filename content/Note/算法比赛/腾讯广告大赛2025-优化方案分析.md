### **核心优化方向概览**

为了提升模型的分数，我们的根本目标是**提升学习到的用户和物品表征（Representations）的质量**。一个高质量的表征空间应该具备更好的“度量”属性，即相似的（用户，正样本物品）对在空间中距离更近，而不相似的（用户，负样本物品）对距离更远。

我们将从以下三个层面系统地进行优化：

1.  **数据层面：优化负采样策略 (Negative Sampling Strategy)**
2.  **损失函数层面：精调对比学习目标 (Contrastive Learning Objective)**
3.  **模型结构层面：增强用户兴趣的捕获能力 (User Interest Modeling)**

---

### **方向一：优化负采样策略——从“随机”到“困难”**

#### **1. 问题定义 (Problem Definition)**

您当前的负采样策略是**均匀随机采样** (`_random_neq` in `dataset.py`)。这种策略在训练初期是有效的，但随着模型能力的增强，随机采样的负样本会变得“过于简单”，模型可以轻易地将它们与正样本区分开。这会导致梯度信息减少，模型学习停滞。

#### **2. 理论依据 (Theoretical Basis)**

对比学习的效率很大程度上取决于负样本的质量。高质量的负样本，即**困难负样本 (Hard Negatives)**，是指那些在当前嵌入空间中与用户表征非常相似，但并非正样本的物品。迫使模型去区分这些困难负样本，能够使其学习到更细粒度的特征差异，从而构建一个判别能力更强的表征空间。

从信息论的角度看，简单的负样本提供的信息熵较低，而困难负样本提供的信息熵更高，能带来更大的模型参数更新。

#### **3. 具体优化策略 (Specific Optimization Strategies)**

**策略1.1: 基于物品流行度的负采样 (Popularity-based Negative Sampling)**

*   **核心思想**: 热门物品通常具有普适性的特征，更容易被错误地推荐给大量用户，因此是天然的困难负样本。
*   **数学原理**: 我们可以根据物品的流行度分布（例如，出现频率的`α`次方，`0 < α < 1`）进行带偏采样。一个常见的采样概率公式为：
    $$ P(i) = \frac{f(i)^\alpha}{\sum_{j \in I} f(j)^\alpha} $$
    其中 `f(i)` 是物品 `i` 的频率，`α` 是一个平滑系数（通常取0.75）。
*   **实施建议**:
    1.  **数据预处理**: 首先需要统计数据集中所有物品的出现频率，构建一个物品流行度表。
    2.  **修改采样逻辑**: 修改 `dataset.py` 中的 `_random_neq` 函数。不再使用 `np.random.randint`，而是使用 `np.random.choice`，并传入根据上述公式计算出的采样概率数组。

**策略1.2: 批内困难负样本挖掘 (In-batch Hard Negative Mining)**

*   **核心思想**: InfoNCE损失已经隐式地利用了批内负采样。我们可以更进一步，在计算损失时，给予那些更“困难”的批内负样本更高的权重。
*   **理论依据**: 在计算 `logits` 后，我们可以识别出那些与 `seq_embs` 相似度最高的负样本。
*   **实施建议** (此项与方向二关联紧密，可结合实施):
    1.  在 `model.py` 的 `compute_infonce_loss` 函数中，计算完负样本相似度 `neg_logits` 后。
    2.  不对所有负样本一视同仁，而是可以设计一种加权方案。例如，可以只选择Top-K个最难的负样本来计算损失，或者根据相似度对损失进行加权。

**策略1.3: 混合采样 (Mixed Sampling)**

*   **核心思想**: 单纯只用困难负样本可能会让模型陷入局部最优，丢失对全局表征空间的探索。一个更稳健的策略是混合使用随机负样本和困难负样本。
*   **实施建议**: 在 `_random_neq` 中，以一定概率（例如50%）执行随机采样，另50%执行基于流行度的困难负采样。

### **方向二：精调对比学习目标——优化InfoNCE损失函数**

#### **1. 问题定义 (Problem Definition)**

标准的InfoNCE损失函数虽然强大，但它有两个主要的敏感点或可优化之处：
1.  **温度系数 `τ` (Temperature `τ`)** 是一个极其关键的超参数，它直接影响了模型对困难负样本的关注程度。
2.  **批内负采样 (In-batch Negative Sampling)** 存在一个固有的统计偏差，即**假阴性 (False Negatives)** 问题：一个批次内的其他样本，对当前用户而言，可能是一个未来的正样本，但我们却强制将其作为负样本推开。

#### **2. 理论依据 (Theoretical Basis)**

*   **温度系数 `τ`**: 在 `softmax` 函数中，`τ` 控制着概率分布的平滑度。
    $$ \text{softmax}(z_i / \tau) = \frac{\exp(z_i / \tau)}{\sum_j \exp(z_j / \tau)} $$
    -   当 `τ` -> 0 时，`softmax` 趋向于一个 `argmax` 函数，损失会集中在最困难的负样本上。
    -   当 `τ` -> ∞ 时，`softmax` 趋向于一个均匀分布，所有负样本的权重趋于一致。
    一个最优的 `τ` 能平衡模型的“惩罚力度”，使其既能区分困难样本，又不至于忽略其他样本。

*   **去偏对比学习 (Debiased Contrastive Learning)**: 为了解决假阴性问题，一些研究工作提出了修正项。其核心思想是，估计一个批内样本为真实负样本的概率，并用此概率来修正损失计算。

#### **3. 具体优化策略 (Specific Optimization Strategies)**

**策略2.1: 系统性地调优温度系数 `τ`**

*   **核心思想**: 将 `self.temp` (当前固定为0.07) 视为一个关键超参数进行实验。
*   **实施建议**:
    1.  在 `main.py` 的 `get_args` 中添加一个新的命令行参数 `--temperature`。
    2.  进行一组控制变量实验，例如尝试 `[0.05, 0.07, 0.1, 0.2]` 等值，观察验证集上分数的变化。这通常是性价比最高的优化之一。

**策略2.2: 引入去偏的对比损失 (Debiased Contrastive Loss)**

*   **核心思想**: 修正InfoNCE的分母项，以降低假阴性样本带来的负面影响。
*   **数学原理** (简化版): 假设我们知道一个负样本 `i` 为真实负样本的概率是 `p_i` (可以基于例如物品流行度来近似)，修正后的logit可以近似为：
    $$ \log \frac{\exp(s^+ / \tau)}{\exp(s^+ / \tau) + \sum_{j=1}^{N} p_j \exp(s_j^- / \tau)} $$
    这是一个更高级的优化，需要更深入的数学推导，但基本思想是为那些“很可能是假阴性”的样本（如非常热门的物品）分配一个较小的权重。
*   **实施建议**:
    1.  在 `compute_infonce_loss` 中，在计算 `neg_logits` 之后，需要引入一个修正项。这需要与负采样的流行度分布结合起来。
    2.  这是一个较复杂的改动，建议在完成策略2.1和方向一之后再尝试。

### **方向三：优化模型结构——更精细地建模用户兴趣**

#### **1. 问题定义 (Problem Definition)**

当前模型使用一个标准的Transformer编码器来处理整个用户行为序列，对所有历史行为一视同仁。然而，用户的下一次点击行为可能同时受到**长期、稳定的兴趣**和**短期、动态的意图**的共同影响。标准Transformer可能无法有效地区分和融合这两种模式。

#### **2. 理论依据 (Theoretical Basis)**

为了更精准地预测下一个行为，模型需要生成一个**上下文感知 (Context-aware)** 且 **目标导向 (Target-aware)** 的用户表征。
*   **上下文感知**: 充分理解历史序列中的复杂依赖关系。
*   **目标导向**: 生成的用户表征应该与“预测下一个点击”这个任务强相关。

#### **3. 具体优化策略 (Specific Optimization Strategies)**

**策略3.1: 引入目标注意力机制 (Target Attention, TA)**

*   **核心思想**: 在传统的自注意力机制之上，增加一层专门建模历史序列与**候选物品 (Candidate Item)** 之间关系的注意力。这使得用户表征不再是“静态”的，而是会根据你正在评估的候选物品动态变化。
*   **数学原理**:
    1.  首先，通过Transformer得到历史序列的表征 `H_seq`。
    2.  当有一个候选物品 `i_c` (例如，一个正样本或负样本) 时，用它的嵌入 `E_c` 作为Query。
    3.  用历史序列的表征 `H_seq` 作为Key和Value。
    4.  计算注意力：
        $$ \alpha = \text{softmax}\left(\frac{(E_c W_Q) (H_{seq} W_K)^T}{\sqrt{d_k}}\right) $$
        $$ U_{c} = \alpha (H_{seq} W_V) $$
    `U_c` 就是针对候选物品 `c` 的动态用户兴趣表征。
*   **实施建议**:
    1.  在 `BaselineModel` 的 `forward` 方法中，在 `log2feats` 之后，需要为 `pos_embs` 和 `neg_embs` 分别计算目标注意力。
    2.  你需要创建一个新的注意力模块（可以复用 `FlashMultiHeadAttention`），其 `query` 来自正/负样本，`key` 和 `value` 来自 `seq_embs`。
    3.  最终用于计算InfoNCE损失的 `seq_embs` 将被这个动态的用户表征 `U_c` 替代。

**策略3.2: 引入长短期兴趣建模 (Long- and Short-term Interest Modeling)**

*   **核心思想**: 设计并行的网络结构来分别捕获长短期兴趣。
*   **实施建议 (例如，一个简化的HSTU思想)**:
    1.  **短期兴趣**: 对最近的K个行为（例如K=10）使用一个独立的、较浅的Transformer或者GRU来建模，得到 `U_short`。
    2.  **长期兴趣**: 使用您现有的、更深的Transformer对整个序列（或一个采样后的长序列）进行建模，得到 `U_long`。
    3.  **融合**: 将 `U_short` 和 `U_long` 通过一个门控机制 (Gating Mechanism) 或简单的拼接+MLP进行融合，得到最终的用户表征。
    $$ U_{final} = \text{Gate}(U_{short}, U_{long}) = \sigma(W_g[U_{short}; U_{long}]) \odot U_{short} + (1 - \sigma(W_g[U_{short}; U_{long}])) \odot U_{long} $$
    这需要在 `log2feats` 函数内部进行较大的结构性修改。

### **1. 分支策略 (Branching Strategy)**

对于这项优化，我建议您从 **`main` 或 `master`** 分支上创建一个新的、独立的分支，例如 `feature/debiased-infonce`。

**理由如下：**

1.  **正交性 (Orthogonality)**: 去偏损失的改动是**完全正交于**模型结构（如长短期兴趣建模）和采样策略（如流行度采样）的。它是一个独立的数学优化，理论上可以与任何模型结构或采样策略叠加使用。
2.  **清晰的因果分析**: 在一个干净的基线模型上实施去偏损失，可以让我们清晰地衡量出**仅由损失函数去偏这一项改动**带来的性能增益或变化。如果在一个已经很复杂的模型上修改，很难判断性能变化是来自于去偏的功劳，还是与其他模块（如长短期兴趣）产生了复杂的交互效应。
3.  **后续合并的灵活性**: 在独立验证了其有效性后，您可以轻松地将这个分支的改动（主要是`compute_infonce_loss`函数）合并到其他表现最好的分支上（例如，未来的`long-short-term-model`分支）。

### **2. 形式化分析与理论推导**

**2.1 问题根源：InfoNCE的偏差**

让我们再次审视标准的InfoNCE损失函数（以批内负采样为例）：

$$ \mathcal{L}_{InfoNCE} = - \log \frac{\exp(\text{sim}(u, i^+)/\tau)}{\sum_{j \in \mathcal{B}} \exp(\text{sim}(u, i_j)/\tau)} $$

这里，`u` 是用户表征，`i+` 是正样本。分母中的求和项 `∑_{j∈B}` 遍历了当前批次 `B` 中所有的样本。这个公式的核心假设是：**批次 `B` 中除了 `i+` 之外的所有样本都是 `u` 的真实负样本**。

然而，这个假设在推荐场景中是**错误**的。一个批次中，另一个用户的正样本 `i_j` 完全有可能是当前用户 `u` 未来会点击的物品，即一个**未被观测到的正样本 (unobserved positive)**。我们将这种样本称为**假阴性 (False Negative)**。

当模型被强制将 `u` 和一个假阴性样本 `i_j` 推开时，实际上是在惩罚一个正确的关联，从而引入了偏差，损害了表征学习的质量。

**2.2 去偏方案：修正概率分布**

去偏对比损失的核心思想是，**从数学上修正这个有偏的采样分布**。Cho et al. (2020) 的工作提供了一个优雅的解决方案。他们证明，有偏分布 `p(i|u)` 和真实分布 `p_+(i|u)` 之间存在如下关系：

$$ p(i|u) = p_+(i|u) - \tau_i p_-(i|u) $$

其中 `τ_i` 是物品 `i` 的采样概率（即它在数据集中出现的概率，也就是我们计算过的**流行度**），`p_-(i|u)` 是其作为真实负样本的概率。

通过一系列推导，可以得到一个修正后的、无偏的损失函数。其核心是修正分母中的每一项 `exp(sim(u, i_j)/τ)`。

修正后的期望值为：
$$ \mathbb{E}_{p_+}[\exp(s_j/\tau)] \approx \mathbb{E}_{p}[\exp(s_j/\tau)] - N\mathbb{E}_{p_n}[\exp(s_j/\tau)] $$
其中，`p`是观测分布，`p_n`是噪声分布（即我们的采样分布）。

最终，我们可以得到一个实用的**去偏对比损失 (Debiased Contrastive Loss)** 的计算方式：

$$ \mathcal{L}_{Debiased} = - \log \frac{\exp(s^+/\tau)}{\exp(s^+/\tau) + \sum_{j=1}^{N} (\exp(s_j^-/\tau) - N \cdot P(j) \cdot \exp(s_j^-/\tau))} $$
这个公式看起来很复杂，但我们可以简化它。更直观且易于实现的一种形式是：

$$ \mathcal{L}_{Debiased} = - \left( s^+/\tau - \log \left( \exp(s^+/\tau) + \sum_{j=1}^{N} \max(0, \exp(s_j^-/\tau) - N P_j) \right) \right) $$
其中 `s+` 和 `s_j-` 分别是正负样本的logits，`N` 是负样本的数量，`P_j` 是负样本 `j` 的采样概率。

**一个更简单且被广泛采用的修正方法是，直接从分母中减去假阴性的期望影响**：

$$ \mathcal{L}_{Debiased} = - \log \frac{\exp(s^+/\tau)}{\exp(s^+/\tau) + (\sum_{j=1}^{N} \exp(s_j^-/\tau) - \sum_{j=1}^{N} P_j)} $$
这个形式在实现上最为简单，我们先从这个版本入手。`P_j` 就是我们在**策略1.1**中计算的**物品流行度概率**。

**2.3 关键依赖：物品流行度**

请注意，**所有去偏方法都强依赖于每个物品的采样概率**。这意味着，我们必须复用**策略1.1**中预计算的`item_popularity.pkl`。这进一步印证了模块化、逐步优化的重要性。

**Correction and Simplification:** The vectorized implementation above is complex and potentially buggy. Let's step back and implement the simpler, more direct correction formula which is more robust.

**Revised, Simpler `compute_infonce_loss_efficient`**
$$ \mathcal{L}_{Debiased} = - \log \frac{\exp(s^+/\tau)}{\exp(s^+/\tau) + \sum_{j=1}^{N} \max(0, \exp(s_j^-/\tau) - P_j)} $$
Note: Here we assume `N=1` for the number of negative samples in the probability `P_j`, so `NP_j` simplifies to `P_j`. This is a common simplification.

```python
# In model.py
# The function needs access to the negative item IDs. We must pass them from the forward call.
def compute_infonce_loss_efficient(self, seq_embs, pos_embs, neg_embs, loss_mask, neg_ids):
    # neg_ids should be the tensor of negative item IDs, shape [B, L]
    
    # L2 Normalization
    seq_embs = F.normalize(seq_embs, p=2, dim=-1)
    pos_embs = F.normalize(pos_embs, p=2, dim=-1)
    neg_embs = F.normalize(neg_embs, p=2, dim=-1)

    # Positive scores
    pos_scores = (seq_embs * pos_embs).sum(dim=-1) # Shape: [B, L]

    # In-batch negative scores
    neg_embs_swapped = neg_embs.transpose(0, 1) # Shape: [L, B, H]
    seq_embs_swapped = seq_embs.transpose(0, 1) # Shape: [L, B, H]
    neg_scores = torch.bmm(seq_embs_swapped, neg_embs_swapped.transpose(1, 2)) # Shape: [L, B, B]
    neg_scores = neg_scores.transpose(0, 1) # Shape: [B, L, B]

    # Calculate exponential terms for the whole batch
    exp_pos_scores = torch.exp(pos_scores / self.temp)
    exp_neg_scores = torch.exp(neg_scores / self.temp) # Shape: [B, L, B]

    # --- NEW CODE: Debiasing Correction ---
    denominator = exp_pos_scores # Start with the positive term
    
    if self.neg_sampling_probs is not None:
        # Get probabilities of all negative items used for keys. These are `neg_ids`.
        # For a query (b, l), the keys are from neg_embs[b', l] for b'=0..B-1
        # The corresponding IDs are neg_ids[:, l]
        # This requires a loop over L, which is inefficient.
        
        # Let's use the simpler formula on the sum.
        # This assumes the batch is a good sample of the overall distribution.
        # This is the approach from the original paper's code.
        sum_exp_neg_scores = exp_neg_scores.sum(dim=-1) # Shape: [B, L]
        
        # The negative items are the positive items from other samples in the batch
        # So we need `pos_ids` from the batch.
        # Let's assume we pass `pos_ids` with shape [B, L]
        pos_probs = self.neg_sampling_probs[pos_ids] # Shape: [B, L]
        
        # The batch size B is the number of "in-batch" negatives
        N = neg_scores.shape[-1]
        
        # The correction term is sum(P_j) for all j in batch
        # For each query, the negatives are the same set (the whole batch)
        # So for each query, the correction is the same constant.
        correction = N * pos_probs.sum(dim=0) # Sum over batch dim, gives shape [L]
        
        debiased_sum_exp_neg_scores = F.relu(sum_exp_neg_scores - correction)
        denominator = exp_pos_scores + debiased_sum_exp_neg_scores
    else:
        # Standard InfoNCE
        denominator = exp_pos_scores + exp_neg_scores.sum(dim=-1)

    # Calculate the loss
    loss = -torch.log(exp_pos_scores / denominator)
    
    # Apply mask
    loss = loss[loss_mask.bool()].mean()
    return loss
```
**Final, Cleanest Implementation:** After reviewing the complexities, the most robust and standard way to implement this is to correct the logits *before* the log-softmax operation.

```python
# In model.py
# Final Recommended Version
def compute_infonce_loss_efficient(self, seq_embs, pos_embs, neg_embs, loss_mask, pos_ids):
    # pos_ids are needed for their probabilities. Shape: [B, L]
    
    seq_embs = F.normalize(seq_embs, p=2, dim=-1)
    pos_embs = F.normalize(pos_embs, p=2, dim=-1)
    neg_embs = F.normalize(neg_embs, p=2, dim=-1)

    pos_scores = (seq_embs * pos_embs).sum(dim=-1) # Shape: [B, L]

    neg_embs_swapped = neg_embs.transpose(0, 1) # Shape: [L, B, H]
    seq_embs_swapped = seq_embs.transpose(0, 1) # Shape: [L, B, H]
    neg_scores = torch.bmm(seq_embs_swapped, neg_embs_swapped.transpose(1, 2)) # Shape: [L, B, B]
    neg_scores = neg_scores.transpose(0, 1) # Shape: [B, L, B]

    logits = torch.cat([pos_scores.unsqueeze(-1), neg_scores], dim=-1) # Shape: [B, L, B+1]

    # --- NEW CODE: Debiasing Correction ---
    if self.neg_sampling_probs is not None and pos_ids is not None:
        # Get probabilities of all positive items in the batch, which serve as negatives
        # pos_ids has shape [B, L]. The negatives for a query at (b, l) are from pos_ids[:, l].
        # Let's reshape pos_ids to [B*L] to get all probs at once
        batch_pos_ids = pos_ids.reshape(-1)
        # Some IDs might be 0 (padding), handle this.
        batch_pos_ids[batch_pos_ids < 0] = 0 # Ensure no negative indices
        probs = self.neg_sampling_probs[batch_pos_ids].reshape(pos_ids.shape) # [B, L]
        
        # For a query (b,l), the negatives are from the whole batch, indexed by b'
        # The items are pos_ids[b', l]. The probabilities are probs[b', l].
        # We need to subtract log(P_j) from the logits s_j.
        # The logits are [B, L, B+1]. The last B entries are neg_scores.
        # We need to subtract log(probs[:,l]) from neg_scores[:,l,:].
        # This requires broadcasting.
        # `probs` is [B, L]. We need [B, L, B].
        probs_reshaped = probs.unsqueeze(0).expand(logits.shape[0], -1, -1) # [B, B, L]
        probs_reshaped = probs_reshaped.transpose(1,2) # [B, L, B]

        # The debiasing term is log(N * P_j). Here N is batch size B.
        # We use a safe log: torch.log(probs_reshaped * logits.shape[0] + 1e-9)
        correction = torch.log(probs_reshaped * logits.shape[0] + 1e-9)
        logits[:, :, 1:] = logits[:, :, 1:] - correction

    # Apply mask and temperature
    logits = logits[loss_mask.bool()] / self.temp
    
    labels = torch.zeros(logits.shape[0], device=logits.device, dtype=torch.long)
    return F.cross_entropy(logits, labels)
```
