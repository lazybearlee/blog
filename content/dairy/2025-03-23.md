## 1. 问题定义
考虑一个具有队列管理机制的无服务器推理系统，其核心目标是在满足服务级别协议(Service-Level Agreement, SLA)约束的前提下，实现系统吞吐量最大化与请求处理延迟最小化的多目标优化。本模型通过建立批处理规模($B$)与系统性能指标之间的量化关系，为动态批处理调节算法提供理论依据。

## 2. 变量定义
### 2.1 决策变量
- $B \in \mathbb{N}^+$: 批处理规模，满足 $1 \leq B \leq B_{\text{max}}$，其中 $B_{\text{max}}$ 表示系统允许的最大批处理量

### 2.2 性能指标
- $L(B): \mathbb{N}^+ \rightarrow \mathbb{R}^+$: 批处理规模为$B$时的平均请求延迟
- $T(B): \mathbb{N}^+ \rightarrow \mathbb{R}^+$: 批处理规模为$B$时的系统吞吐量（请求数/秒）
-  $Q \in \mathbb{N}$: 当前待处理请求队列长度
- $r \in \mathbb{R}^+$: 单位时间请求到达速率

### 2.3 系统参数
- $L_{\text{target}} \in \mathbb{R}^+$: SLA规定的延迟阈值
- $\alpha, \beta, \lambda \in \mathbb{R}^+$: 目标函数权重系数

## 3. 参数估计

- $W_t \in \mathbb{R}^{n \times n}$: 滑动窗口数据矩阵，存储最近n个观测点$(B_i, Q_i, L_i)$
- $\theta = [\gamma_1, \gamma_2, \delta]^T$: 待估计参数向量
### 在线估计目标函数
$$
\min_\theta \sum_{i=1}^n (L_i - (L_0 + \gamma_1 B_i + \gamma_2 Q_i))^2 + \lambda \|\theta\|_2^2
$$

## 4. 模型构建
### 4.1 延迟建模
系统延迟由基础处理延迟与动态延迟分量共同构成：
$$
L(B) = L_0 + f(B, Q) \tag{1}
$$
其中：
- $L_0$表示固定延迟分量（包括基础服务调用等）
- $f(B, Q)$表征批处理机制引入的延迟变化项，满足：
  $$
  \frac{\partial f}{\partial B} > 0, \quad \frac{\partial f}{\partial Q} > 0 \tag{2}
  $$

通过实验数据分析，建立线性延迟增长模型：
$$
f(B, Q) = \gamma_1 B + \gamma_2 Q \tag{3}
$$
式中：
- $\gamma_1$: 批处理规模边际延迟系数（秒/请求）
- $\gamma_2$: 队列等待边际延迟系数（秒/请求）

### 4.2 吞吐量建模
系统吞吐量与批处理效率函数$g(B)$正相关：
$$
T(B) = r \cdot g(B) \tag{4}
$$
其中$g(B)$满足：
$$
\begin{aligned}
&g: \mathbb{N}^+ \rightarrow (0,1] \\
&\frac{dg}{dB} > 0 \\
&\lim_{B \to \infty} g(B) = 1 
\end{aligned} \tag{5}
$$

采用指数饱和函数描述资源利用效率：
$$
g(B) = 1 - e^{-\delta B} \tag{6}
$$
式中$\delta$为系统吞吐特性系数。

## 5. 优化问题
### 5.1 目标函数
定义复合优化目标：
$$
\begin{aligned}
\min_{B} \ & \alpha (L_0 + \gamma_1 B + \gamma_2 Q) + \lambda \max\{0, L(B)-L_{\text{target}}\} \\
& - \beta r (1 - e^{-\delta B}) \\
\text{s.t.} \ & B \in \{1,2,...,B_{\text{max}}\} \\
& \theta \text{ 每 } T \text{ 秒更新一次}
\end{aligned}
$$
该函数包含三个关键分量：
1. 基础延迟惩罚项：$\alpha L(B)$
2. SLA违规惩罚项：$\lambda \max\{0, L(B)-L_{\text{target}}\}$
3. 吞吐量奖励项：$-\beta T(B)$

### 5.2 约束条件
$$
\begin{aligned}
&\text{决策空间约束:} & B \in \mathbb{N}^+,\ &1 \leq B \leq B_{\text{max}} \\
&\text{SLA硬约束:} & L(B) \leq L_{\text{target}} 
\end{aligned} \tag{8}
$$


## 算法伪代码
--------------------------------------------------

````pseudocode
// 输入参数：
// α, β, λ：调节权重与惩罚参数
// L0：基本延迟（从系统初始指标中估计）
// γ1, γ2：延迟增幅参数
// δ：吞吐提升参数
// L_target：SLA规定的最大延迟上限
// r：单位时间请求到达率
// B_max：系统允许的最大批处理大小

// Q：当前队列长度，由内部监控获得

// 定义目标函数 F(B)
function F(B, Q):
    L = L0 + γ1 * B + γ2 * Q            // 当前批处理下估计的平均延迟
    penalty = λ * max(0, L - L_target)    // 延迟超出 SLA 的惩罚项
    throughput = r * (1 - exp(-δ * B))     // 批处理带来的吞吐提升
    return α * L + penalty - β * throughput

// 主动态调整循环（闭环反馈，每个周期重新计算最优B）
while true:
    // 1. 获取当前队列长度Q以及其他监控指标
    Q = getCurrentQueueLength()        // 内部监控
    // 2. 更新系统参数（如 L0, r 等，可采用在线估计）
    L0 = updateBaseLatency()             // 从Prometheus中提取最低延迟
    r  = updateArrivalRate()              // 结合 revision_app_request_count 指标

    // 3. 搜索最优批处理大小 B_opt
    bestB = 1
    bestF = F(1, Q)
    for B from 2 to B_max do:
        currentF = F(B, Q)
        if currentF < bestF then:
            bestF = currentF
            bestB = B
        end if
    end for

    // 4. 将最优的批处理大小设置为当前系统的动态批处理大小
    setDynamicBatchSize(bestB)

    // 5. 等待一个调节周期后继续更新（如 5 秒钟）
    sleep(adjustment_interval)
end while
````

--------------------------------------------------

【说明】
1. 函数 getCurrentQueueLength()、updateBaseLatency() 与 updateArrivalRate() 分别用来实时获取内部队列长度、系统基本延迟和请求到达率，可以从 Prometheus 指标与内部监控中提取。  
2. setDynamicBatchSize() 为将求得的最优批处理大小 bestB 更新到实际使用的 batcher 中，以便后续批处理时使用。  
3. 调整周期（adjustment_interval）可根据实际调控时延要求进行设置。
