# 多模态生成模型推理与调度 24 周学习与工作结合计划（v0.2）

> 周期：24 周（12 个两周 Sprint）  
> 节奏：每周 3 天推进工程（冷启动、热切换、虚拟化、细粒度调度），3-4 天系统学习并产出小型验证与笔记  
> 范围：聚焦图片/视频/音频生成模型的推理与调度；不包含大语言模型；量化/算子优化/蒸馏由专门的 Infra 推理团队负责

---

## 1. 目标与边界

- 目标
  - 6 个月内：把冷启动、模型热切换（offload/onload）、引擎部署与虚拟化、混合部署与细粒度调度跑通到生产可用，并建立稳定的度量与运维体系。
  - 学习反哺工作：每个 Sprint 都有直接落地的工程产出与明确指标改进。

- 边界与假设
  - 尽量不更换推理引擎（TensorRT/ONNX Runtime/PyTorch 选其一或二），热切换指同一引擎进程内更换模型权重与运行态，不重启进程。
  - 不做模型结构/算子层改动（由 Infra 团队承担）。我们负责装配、调度、资源与工艺侧优化。
  - 集群扩缩容与通用云原生能力由平台团队提供；我们定义接口、策略与行为，落地在模型与调度层。

---

## 2. 问题-指标映射

- 冷启动（Cold Start）
  - 指标：`T_container_boot`、`T_engine_ready`、`T_model_ready`、`T_first_infer`
  - 目标：前 4-6 周建立稳定基线，定位 30%-50% 可优化空间（并行/流水化加载、流式加载、页缓存与预热）。

- 热切换（Hot Switch：offload/onload）
  - 指标：`T_offload`、`T_onload`、`Switch_impact`、`Warm_hit_rate`
  - 目标：同引擎内切换做到秒级/子 10 秒级，对在服请求影响可控；形成“热模型池 + 驱逐”策略。

- 虚拟化与混合部署
  - 指标：`VRAM_usage`、`VRAM_fragmentation`、`MIG_partition_util`、`Pinned_host_mem`、`NVMe_bw`/`GDS_bw`、`Container_image_size`、`Layer_cache_hit`
  - 目标：引擎与模型解耦；基础镜像固化引擎，模型以工件分层/按需注入。

- 细粒度调度
  - 指标：`SLA_met_rate`、`Queue_time_p95/p99`、`E2E_latency_p95/p99`、`GPU_sec_per_request`、`Placement_success`、`Preemption_cost`、`Eviction_count`
  - 目标：建立“模型槽位/资源画像”，在 GPU/MIG/内存/IO 维度做可行放置与回收策略。

---

## 3. 工程路线（高层）

- 工件与加载：统一权重格式（safetensors/分块），支持 mmap/分块/流式读取；建立 NVMe → pinned host mem →（GDS 可选）→ VRAM 的加载流水线。
- 运行时重绑定：同进程“解绑→加载/映射→绑定→预热”的可观测状态机；对外暴露切换窗口与限流信号。
- 镜像与虚拟化：基础镜像固化引擎，模型以层/卷注入；必要时结合 MIG/MPS 做实例密度与隔离。
- 调度与扩缩容：定义“模型槽位（权重显存/激活显存/IO 带宽）”与节点画像；扩容前置预热，缩容结合热度与驱逐代价。
- 可观测性：加载/切换分解时延、IO 吞吐、显存使用、错误码全打点到 Prometheus，并出面板。

  | 第1-2周   | GPU内存管理、CUDA基础 | CS149前5讲 或 NVIDIA DLI     | 1-2天 |
  | 第3-4周   | 深度学习框架原理      | CMU 10-414前6讲              | 1-2天 |
  | 第5-6周   | NCCL、集合通信        | NCCL文档 + xDiT代码          | 1天   |
  | 第19-20周 | K8s、容器化           | NVIDIA Container Toolkit文档 | 1天   |

- 工程（3 天）

  - [ ] “引擎常驻，模型路径可切换”的最小 PoC（onload/offload 同步版）。
  - [ ] 选定代表性图像生成模型，固定参数（分辨率/步数）维护基线。
  - 产出：`baseline.md`、Grafana 面板、PoC 分支。
- 学习（3-4 天）
  - [ ] 生成模型推理基本原理（[#GEN-PRIMER]）。
  - [ ] 引擎部署与管线（[#RT-DEPLOY]、[#RT-TRT-SD]、[#RT-ONNX]）。
  - [ ] 模型加载：safetensors/mmap（[#IO-MEM]）、Diffusers 管线走读（[#IND-DIFFUSERS]）。

### Sprint 2（周3-4）——流式加载与并行预热
- 工程（3 天）
  - [ ] 分块/并行加载 + 绑定流水线，重叠 IO 与初始化。
  - [ ] 热模型池原型：LRU + TTL + 手动 Pin。
  - [ ] 切换期限流与回退（Busy/Drain 信号）。
  - 产出：`hot-switch-pipeline.md`、实验记录与对比图。
- 学习（3-4 天）
  - [ ] Diffusion/DiT 等推理路径与内存峰值来源（[#DIFF-CORE]）。
  - [ ] CUDA 内存管理与 GDS（[#CUDA-MEM]、[#IO-GDS]）。

### Sprint 3（周5-6）——虚拟化与镜像分层
- 工程（3 天）
  - [ ] 基础镜像固化引擎，模型以层/卷注入；同容器内完成热切换。
  - [ ] 与容器云团队评审镜像/卷/生命周期钩子与缓存层设计。
  - 产出：镜像/卷设计草案与评审结论。
- 学习（3-4 天）
  - [ ] NVIDIA 容器/驱动、GPU Operator、MIG/MPS（[#NV-STACK]）。
  - [ ] K8s GPU 设备插件/度量（[#K8S-GPU]）；工件与模型注册表（[#ART-REG]）。

### Sprint 4（周7-8）——MIG/MPS 与实例密度
- 工程（3 天）
  - [ ] 测试集群试跑 MIG/MPS，对比密度/抖动/隔离与时延。
  - [ ] 显存碎片与实例放置的观测与告警。
  - 产出：`placement-notes.md`、面板与告警规则。
- 学习（3-4 天）
  - [ ] MIG 用户指南与策略（[#MIG-GUIDE]）。
  - [ ] 混部与资源画像/放置算法（[#SCHED-POL]）。

### Sprint 5（周9-10）——热切换稳定化与回收策略

  - [ ] 多因子驱逐：热度、体积、加载时延、SLA 风险。
  - 产出：`switch-policy.md`、稳定性与尾延迟对比。

  - [ ] 端到端观测/Tracing（[#OBS]）。
